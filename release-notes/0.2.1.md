swift_tar 0.2.1 fixes one Windows message. Every other platform behaves as in 0.2.0.

swift_tar 0.2.1 修正一則 Windows 上的訊息。其他平台的行為與 0.2.0 相同。

## Changes since 0.2.0 / 與 0.2.0 的差異

- **Windows: `-c --zip` names an unreadable file correctly.** When a file could not be read, a name outside the ANSI code page was printed as `?`, so `한글.txt` and `😀.txt` were both reported as `src/??.txt` and could not be told apart. Both now appear under their real names. The count and the exit status were already right; only the name was lost. The fix is in swift_tar's ZIP bridge and in a small patch to libarchive's Windows disk reader, which the Windows build alone applies.
  **Windows：`-c --zip` 正確說出讀不到的檔名。** 讀不到檔案時，超出 ANSI 字碼頁的名稱會被印成 `?`，於是 `한글.txt` 與 `😀.txt` 都回報成 `src/??.txt`，無從分辨。現在兩者都以原名出現。計數與退出碼本來就對，只有名稱壞掉。修正在 swift_tar 的 ZIP bridge，以及 libarchive Windows 磁碟讀取端的一份小 patch，只有 Windows 建置會套用。
- **The scoop bucket is `lzfse2`.** The README told you to add the bucket as `lzfse2` and then install from `raliclo`, which does not exist. Use the commands below.
  **scoop bucket 名為 `lzfse2`。** README 原本叫你以 `lzfse2` 加入 bucket，卻從不存在的 `raliclo` 安裝。請用下方的指令。

The six archives are the same set as 0.2.0, built by GitHub Actions with Swift 6.4.2, each with a `.sha256` and a build-provenance attestation:

六份封存與 0.2.0 相同，由 GitHub Actions 以 Swift 6.4.2 建置，各附 `.sha256` 與建置來源證明：

```sh
gh attestation verify swift_tar-0.2.1-linux-x86_64-musl.tar.zst -R raliclo/swift_tar
```

## Install / 安裝

```sh
brew install raliclo/swift_tar/swift_tar                                  # macOS arm64
scoop bucket add lzfse2 https://github.com/raliclo/lzfse2                 # Windows x86-64
scoop install lzfse2/swift_tar
zsh install.zsh 0.2.1                                                     # any of the six
```
