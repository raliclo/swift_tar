swift_tar 0.2.2 hardens parallel ZIP creation against files swapped while it runs, and stops a needless note when reading.

swift_tar 0.2.2 讓平行建立 ZIP 時不受執行中被換掉的檔案影響，並拿掉讀取時一行多餘的提示。

## Changes since 0.2.1 / 與 0.2.1 的差異

- **`-c --zip -n N` (macOS and Linux): a file swapped after it was listed is left out.** With several threads, a file is read some time after the walk listed it. If in that time it was replaced by another file, a symlink or a FIFO, 0.2.1 stored the other file's bytes under the original name, followed the symlink (without `-h`) and stored what it pointed to, or hung on the FIFO. Now such a member is left out, named on stderr as `cannot open, left out`, and counted toward a non-zero exit status, as an unreadable file already was. `-h` still stores what a symlink points to. Windows has no parallel ZIP path and was not affected.
  **`-c --zip -n N`（macOS 與 Linux）：列出之後被換掉的檔案會略過。** 使用多個執行緒時，檔案在走訪列出後過一段時間才被讀取。若這段時間內它被換成另一個檔案、symlink 或 FIFO，0.2.1 會把另一個檔案的內容以原名存入、跟隨 symlink（未加 `-h` 時）存入它指向的內容，或卡在 FIFO 上。現在這樣的成員會被略過，在 stderr 以 `cannot open, left out` 說出名稱，並計入非零的退出碼，與讀不到的檔案相同。`-h` 仍存入 symlink 指向的內容。Windows 沒有平行 ZIP 路徑，不受影響。
- **`-x` and `-t` accept a codec flag silently.** Reading detects the codec by itself, so `-x --zstd` or `-t -z` has nothing to do. 0.2.1 printed `Note: codec flags only affect -c` each time; GNU tar and bsdtar say nothing, and scripts written for them, such as multiscp extracting with `-x --zstd`, got the note on every run. It is gone. Two codec flags at once are still refused.
  **`-x` 與 `-t` 安靜接受壓縮旗標。** 讀取會自行判斷壓縮格式，所以 `-x --zstd` 或 `-t -z` 沒有事可做。0.2.1 每次都印出 `提示：引擎旗標僅影響 -c`；GNU tar 與 bsdtar 不會說話，為它們寫的腳本（例如以 `-x --zstd` 解開的 multiscp）每次執行都帶著這行提示。現在拿掉了。同時給兩個壓縮旗標仍會被拒絕。
- **`install.zsh` puts the old swift_tar back if the new one fails after replacing it.** This is in the script in the repository, so it applies to whichever version you install with it.
  **`install.zsh` 在新的 swift_tar 換上之後才失敗時，會把舊版放回去。** 這是 repository 裡的腳本，所以不論用它安裝哪個版本都適用。

The six archives are the same set as 0.2.1, built by GitHub Actions with Swift 6.4.3, each with a `.sha256` and a build-provenance attestation:

六份封存與 0.2.1 相同，由 GitHub Actions 以 Swift 6.4.3 建置，各附 `.sha256` 與建置來源證明：

```sh
gh attestation verify swift_tar-0.2.2-linux-x86_64-musl.tar.zst -R raliclo/swift_tar
```

## Install / 安裝

```sh
brew install raliclo/swift_tar/swift_tar                                  # macOS arm64
scoop bucket add lzfse2 https://github.com/raliclo/lzfse2                 # Windows x86-64
scoop install lzfse2/swift_tar
zsh install.zsh 0.2.2                                                     # any of the six
```
